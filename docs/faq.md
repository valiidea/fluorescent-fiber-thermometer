# 常见问题与排错

## 能直接测温或烧录到单片机吗？

不能。仓库没有硬件驱动、采样时序、通信协议、标定数据或固件工程。名称描述教学主题，不表示已经实现可用测温产品。

## feature / tau 是寿命或摄氏度吗？

不是。使用的是归一化位置差，结果没有真实时间尺度。温度映射需要独立标定，本项目没有实现。

## 为什么没有真实噪声或探头数据？

输入由数学公式生成，用于展示模块间关系。当前模型不能代表实际探头、模拟前端或噪声分布。

## 出现 make: command not found / cc: command not found

安装 Make 与 C 编译工具，并检查 PATH。macOS 可安装 Command Line Tools；Windows 可使用 WSL。

## 链接时提示 exp、log 或 sin 未定义

优先用仓库 Makefile，它会在源文件之后链接 `-lm`。若自行编译，保留标准数学库链接选项。

## 为什么改了编译选项，结果没有重新构建？

Make 不把命令行选项变化视为文件依赖变化。选择新的 `BUILD` 目录，或用 `make -B` 强制重建。

## 分析返回 0 / Example input rejected

检查窗口宽度、范围和先后顺序；背景扣除后必须满足 `early > late > 0`，相关数值必须有限。完整约束见 [接口参考](api.md)。默认合成输入应通过；修改后出错时请保留最小复现。

## 为什么反馈和 feature 变化不一致？

反馈比较的是早期窗口均值与示意目标，而 `feature` 描述衰减形状，两者不是同一指标。文字建议也不会驱动任何输出。

## 可以商用或复用吗？

仓库文件采用 MIT 许可证，使用时需保留版权与许可声明；以 [LICENSE](../LICENSE) 完整文本为准。

## 新的 est_fit 返回 0，为什么却是成功？

新接口返回状态枚举，`EST_OK == 0`；旧 `demo_analyze` 返回布尔值，1 表示成功。请按各自接口检查，不要混用。详见 [API](api.md)。

## log 方法失败多，是否意味着 nls 总是更好？

不是。log 无法处理扣背景后的非正点，NLS 则对尖峰和饱和可能更敏感。阅读[实验报告](../reports/reference/results.md)时同时比较误差和拒绝率；不同成功子集不能直接当作同一总体。

## 为什么没有生成图？

`make experiment` 默认只生成数值和 Markdown 报告。图表需要可选 Matplotlib，命令见[快速开始](getting-started.md)。

## 能接收设备导出的 CSV 吗？

只能读取[规定格式](cli.md)：每帧32点、背景列和递增帧号。即使转换成功，也需要单独验证时间轴、探头模型、背景和标定，才能讨论真实设备含义。
